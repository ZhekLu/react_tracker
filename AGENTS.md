# Tracker change records

For every tracker change, add or update a concise entry in `docs/feature-log.md`.
Record small features and fixes as well as larger changes. Include user-visible
behavior, special syntax or handling, known bugs/TODOs, and relevant validation.
Mark unfinished work explicitly; do not describe planned behavior as delivered.
Keep entries short and link to detailed documentation when needed.

Preserve user-authored plans, notes, progress, and unrelated working-tree changes.

Commit each completed change, fix, or feature promptly together with its relevant
tests and feature-log entry. Run the appropriate checks before committing. Keep
commits focused; do not accumulate unrelated work into a later bulk commit.
Never include local databases, credentials, diagnostics, backups, or build output.
